# Тесты Domiary

Пилот основного варианта ADR-007: отдельное расширение `DomiaryTests`,
движок YAxUnit и тонкий клиент на компьютере. В `src/` тестов нет;
в APK движок и тестовое расширение не включаются.

## Запуск

Windows, PowerShell 7, установленная платформа **8.5.1.1529** с `1cv8.exe`,
`1cv8c.exe` и `ibcmd.exe`. Лицензия платформы должна позволять запуск клиента.

```powershell
# Первый запуск / обновление исходников в тестовой базе:
pwsh -NoProfile -File tools/run-tests.ps1 -Prepare

# Повторный запуск без загрузки и изменения свойств расширений:
pwsh -NoProfile -File tools/run-tests.ps1

# Проверка красного пути: намеренно возвращает 1.
pwsh -NoProfile -File tools/run-tests.ps1 -IncludeNegativeControl
```

`-V8Path` / `V8_PATH` задают путь к `1cv8.exe`; иначе выбирается самая новая
установленная 8.5, как в `check-config.ps1`. Проверенная версия приведена выше;
совместимость других версий этим spike не подтверждена. `-TimeoutSeconds`
ограничивает ожидание клиента (по умолчанию 120 секунд).

Цель фиксирована: **`.build/ib` текущего worktree**. Скрипт не принимает другую
базу, не удаляет существующую и удерживает общий `.build/config.lock`.
Не запускай другие сеансы в этой базе одновременно. `-Prepare` загружает
`src/` только на чтение из файлов в временную базу, устанавливает отсутствующий
YAxUnit и обновляет собственное тестовое расширение. Для этих двух расширений
отключаются SafeMode и защита от опасных действий: это требование официальной
инструкции YAxUnit для чтения JSON, динамического вызова тестов и записи отчёта.
Не применяй такую настройку к рабочей базе.

Неизвестные расширения, другая версия или изменённое содержимое YAxUnit
блокируют подготовку, а не заменяются автоматически. Перед каждым прогоном
скрипт сравнивает канонические выгрузки основной конфигурации и тестового
расширения из базы с файлами проекта. При расхождении нужен `-Prepare`;
автоматического повторного запуска загрузки после ошибки нет.

Код **0** — точный выбранный состав тестов выполнен без ошибок и пропусков.
Код **1** — красные тесты либо ошибка подготовки/запуска/отчёта.
`1cv8c.exe` сам по себе возвращает 0 и при падении assertion; скрипт проверяет
также файл `exitCode` YAxUnit, состав JUnit и ошибки на уровне набора.
Пути JUnit и `result.json` выводятся в консоль. Каждый запуск сохраняется
отдельно в `.build/reports/tests/<UTC-время>-<id>/`: JSON запуска, JUnit,
коды, счётчики, SHA-256 исходников, список расширений, логи и контрольные выгрузки.
При блокировке до старта отчёта JUnit может не быть; это не успешный прогон.

## Структура и выбор тестов

```text
tests/
  DomiaryTests/
    Configuration.xml                 # каноническая выгрузка 8.5, формат 2.21
    Languages/Русский.xml              # заимствованный язык основной конфигурации
    CommonModules/Тесты_ПилотКлиентСервер.xml
    CommonModules/Тесты_ПилотКлиентСервер/Ext/Module.bsl
```

`ПроверкаСложения`: `1 + 1 = 2`; `ЗаведомоПадающий`: `1 + 1 = 3`.
Оба зарегистрированы в `ИсполняемыеСценарии`, оба исполняются на клиенте и
сервере. Обычный запуск выбирает первый и 15 тестов модуля
`Тесты_ПовторяемостьКлиентСервер` (32 выполнения);
`-IncludeNegativeControl` дополнительно выбирает второй (34 выполнения,
2 ожидаемых падения).
Это **пилотный runner**, не автоматическое обнаружение будущих тестов:
при добавлении реальных модулей обнови `$tests` и ожидаемые контексты в
`tools/run-tests.ps1`. Отрицательный контроль не должен попадать в обычную
регрессионную выборку.

Тесты повторяемости: создание и проверка правил; перевод четырёх значений
перечисления и отказ для пустого/неверного значения; следующие даты для дней,
недель, месяцев и лет (N = 1 и N > 1); конец месяца и високосные годы;
ближайшая дата до/на отсчёте, на точке ряда и между точками; отсутствие дрейфа
после февраля; сохранение времени суток; далёкие даты; единичные представления
и склонения (включая 11–14, 21, 22, 101, 111–114); ошибки аргументов.

## Зависимость YAxUnit

- Официальный проект: <https://github.com/bia-technologies/yaxunit>.
- Проверенный последний stable release на момент spike: **25.12**.
- Только официальный asset:
  <https://github.com/bia-technologies/yaxunit/releases/download/25.12/YAxUnit-25.12.cfe>.
- SHA-256: `805a2277c997a3c24be0b0d080696479e91e4a15ed7e27aaf3991a7346522d70`.
- Лицензия **Apache-2.0**: <https://github.com/bia-technologies/yaxunit/blob/25.12/LICENSE>.
- CFE хранится только в игнорируемом `.build/vendor/`, в git не поставляется.
  Первому скачиванию нужен интернет; повторный запуск с локальным asset — без него.
- Обновление осознанное: выбери официальный release, проверь лицензию и digest,
  заново выполни оба контрольных прогона, обнови версию/digest/внутренний hash-sum
  в runner и этот README. Скрипт не обновляется на `latest` автоматически.
- Зависимость нужна только для разработки. Без неё приложение работает,
  но автоматические тесты этого runner заблокированы. Запасной путь описан
  в ADR-007, здесь не реализован.

Результаты и ограничения: [отчёт spike](../docs/spike/2026-10-yaxunit.md).
