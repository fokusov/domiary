# Словарь интерфейса Domiary

**Статус:** Accepted — все рекомендации §7 утверждены Игорем 2026-10-02
**Дата:** 2026-10-02
**Для кого:** все агенты и контрибьюторы, которые пишут тексты, видимые пользователю
**Связано с:** [PRD.md](PRD.md) §3, §35, §44 · [ARCHITECTURE.md](ARCHITECTURE.md) §23, §26 · [ADR-001](adr/ADR-001-naming.md)

Единый словарь слов, которыми приложение говорит с пользователем. Внутри Domiary может быть сколь угодно «1С-ной» (PRD §44) — наружу выходят только слова из этого документа.

---

## 1. Как пользоваться словарём

- Один смысл — одно слово. Если в одном месте «вещь», она не становится «позицией», «объектом» или «имуществом» в другом.
- Пользователь видит **синонимы** из §2, а не имена метаданных: `ПоказанияСчетчика`, `Хроника`, `ВещиСервер` — только в коде.
- Названия разделов и вкладок утверждаются вместе с картой экранов; слова для них берутся отсюда (§3).
- Названия, помеченные «★», были спорными; решения зафиксированы в §7.

## 3. Имена разделов

Зафиксировано в PRD §44:

- «Что требует внимания» — главный экран;
- «Мои вещи»;
- «Что нужно сделать»;
- «Платежи»;
- «Накопления»;
- «История».

Для остальных разделов (до утверждения карты экранов) используем:

- «Обслуживание» — правила и расписание;
- «Счётчики», «Документы»;
- «Долги», «Планируемые покупки»;
- «Настройки», «Резервная копия», «Экспорт».

Вкладки навигации утверждает Игорь вместе с картой экранов (направление — ARCHITECTURE §23).

## 4. Запрещённые слова

Не появляются ни в одном тексте, который видит пользователь:

| Слово | Чем заменить |
|---|---|
| справочник | называть сущность: «Вещи», «Категории», «Места», «Счётчики» |
| документ (в смысле 1С: запись с проведением) | «событие» или действие: «покупка», «оплата», «обслуживание». Файлы пользователя «документами» называть можно и нужно (§2) |
| провести, проведение, проведён | «выполнить», «отметить», «сохранить» |
| записать (о данных) | «сохранить» |
| регистр | не появляется в интерфейсе; при необходимости — «данные», «история» |
| реквизит | «поле» |
| перечисление | просто значение: «Вещь продаётся» |
| элемент, группа, владелец (о записях) | конкретное имя: «вещь», «категория», «дом» |
| форма (об экране) | «карточка», «экран», «окно» |
| обработка | действие: «Резервная копия», «Экспорт» |
| конфигурация | «приложение» |
| объект (любая запись базы) | конкретное имя: «вещь», «задача», «платёж» |
| контрагент | имя человека или компании: «Сергей», «ТеплоСервис» |
| номенклатура | «вещи», «категории» |
| ТМЦ, склад, материальные ценности | «вещи», «дом» |
| регламент | «обслуживание», «расписание» (в PRD §9 — внутренний термин, не для интерфейса) |
| проводка, Дт/Кт, баланс | не используем; о деньгах говорим «остаток»: «Осталось 5 000 ₽» |
| пользователь | «вы» (со строчной) |
| данный (канцелярит) | «этот», «такой» или просто опустить |

Дополнение: технические идентификаторы (`ВещиСервер`, `ПоказанияСчетчика`) в пользовательских текстах не появляются никогда.

## 5. Стиль сообщений

**Тон.** Спокойный, дружелюбный, домашний — как толковый сосед, а не как бухгалтерия. Без канцелярита, без восклицаний, без шуток в сообщениях об ошибках.

**Обращение.** Кнопки и подсказки — повелительной формой без местоимений: «Добавьте вещь». Сообщения от приложения — «вы» со строчной (§7.5).

**Длина.** Кнопка — 1–2 слова. Заголовок экрана — до 3 слов. Сообщение — 1–2 предложения; всё длиннее — в подсказку или документацию.

**Ошибки** строятся по схеме: **что случилось (обычными словами) + что сделать**. Без кодов ошибок и без «обратитесь к администратору»: приложение домашнее, администратора нет. Технические детали пишем в журнал, введённые пользователем данные не теряем.

**Пустые состояния** — три части: что здесь появится → с чего начать → кнопка. Никогда не «Данные не найдены» и не «Список пуст».

**Подтверждение удаления.** Назвать объект по имени и сказать, что будет с данными. Кнопки — действия: «Удалить» / «Оставить», не «Да» / «ОК». Если у объекта есть история — упомянуть, что она удаляется вместе с ним.

**Успех** — коротко и без парадов: «Сохранено», «Добавлено». Не заставляем нажимать «ОК» после каждого шага.

**Глаголы действий** — везде одни и те же:

| Действие | Как пишем |
|---|---|
| новая сущность | «добавить» (вещь, дом, платёж) |
| правка | «изменить» |
| удаление | «удалить» |
| задача сделана | «отметить выполненной» |
| платёж внесён | «отметить оплаченным» |
| срок двигается | «перенести срок» |
| деньги в накопление | «пополнить» |
| цифры со счётчика | «внести показания» |

**Даты и суммы.** В сообщениях — по-человечески: «14 мая», «через 3 дня», «просрочено на 4 дня». В полях и таблицах допустим краткий формат. Суммы — «32 990 ₽», знак рубля после числа.

## 6. Примеры: плохо → хорошо

| Плохо | Хорошо | Что не так |
|---|---|---|
| «Элементы справочника „Вещи“ не найдены». | «Здесь появятся ваши вещи. Добавьте первую — например, пылесос или дрель.» — кнопка «Добавить вещь» | Пустое состояние продаёт пользу, а не звучит как 1С |
| «Ошибка при записи объекта! Обратитесь к администратору». | «Вещь не сохранилась. Попробуйте ещё раз.» | Что случилось + что сделать; администратора в домашнем приложении нет |
| «Поле „Наименование“ не заполнено!». | «Укажите название — без него вещь не найти в поиске.» | Объясняем смысл поля, а не отчитываем за «реквизит» |
| «Вы действительно хотите удалить выбранный объект? Да / Нет». | «Удалить „Пылесос Dyson V8“? Вещь и её история исчезнут навсегда.» — «Удалить» / «Оставить» | Имя объекта, последствия, кнопки-действия |
| «Документ „ПоказанияСчетчика0001“ успешно проведён!». | «Показания сохранены. Расход за май — 8 м³.» | Внутреннее имя не светится, глагол пользовательский |
| «Задача просрочена. Дата планового выполнения: 05.09.2026 00:00:00». | «Обслуживание котла просрочено на 4 дня. Отметьте выполненным или перенесите срок.» | Человеческая дата и два понятных выхода |
| «Строки не найдены». | «По запросу „фильтр“ ничего нет. Проверьте написание или добавьте новую вещь.» | Поиск — тоже пустое состояние |
| «Напоминание: срок выполнения задачи истекает!». | «Через 3 дня — замена фильтра воды.» | Уведомление называет дело, а не «срок задачи» |
| «Невозможно восстановить данные. Код ошибки: 0x80070057». | «Эта копия не подходит — она из другой версии приложения. Ваши данные мы не меняли.» | Без кодов; главное — данные целы |

## 7. Решения ★ (утверждены 2026-10-02: везде выбрана рекомендация)

### 7.1. Как называть объект недвижимости: «Дом», «Недвижимость» или «Объект»

- **«Дом» — рекомендация.** Коротко и тепло, совпадает с идеей продукта («история дома»): «Мои дома», «Добавьте ваш дом». Минус: гараж или мастерская «домом» звучат непривычно.
- **«Недвижимость».** Точно для любых объектов. Минус: официально, «риелторский» тон.
- **«Объект».** Нейтрально. Минус: канцелярит, слово ни о чём — и похоже на 1С.

Используем «дом» в широком смысле; в подсказках перечисляем: «дом, квартира, дача, гараж».

### 7.2. Как называть место хранения: «Место», «Место хранения» или «Помещение»

- **«Место» — рекомендация.** Коротко, покрывает и кухню, и полку: «Кухня → Шкаф → Полка 2».
- **«Место хранения».** Точнее для шкафа и коробки, но длинно и со «складским» оттенком.
- **«Помещение».** Хорошо для комнат, но не покрывает полку и коробку.

### 7.3. Как называть обязательство: «Платёж», «Регулярный платёж» или «Обязательство»

- **«Платёж» — рекомендация.** Бытовое слово; раздел «Платежи» уже зафиксирован в PRD §44. Действие: «отметить оплаченным».
- **«Регулярный платёж».** Точнее передаёт суть (расписание), длинно для списков; годится для подсказок.
- **«Обязательство».** Точный внутренний термин (ADR-001), но в интерфейсе звучит юридически.

### 7.4. Как называть цель накоплений: «Накопление», «Цель» или «Цель накопления»

- **«Накопление» — рекомендация.** Раздел «Накопления» уже в PRD §44; «пополнить накопление „Отпуск“» звучит естественно.
- **«Цель».** Короче, но двусмысленно: цель бывает и у задачи.
- **«Цель накопления».** Точно, но длинно; запасной вариант для подсказок.

### 7.5. Обращение к пользователю: «вы» или «ты»

- **Повелительная форма без местоимений — рекомендация** для кнопок и подсказок: «Добавьте вещь», «Выберите категорию».
- **«Вы» со строчной** — в сообщениях от приложения: «Мы сохранили копию ваших данных». Совместимо с первым вариантом.
- **«Ты».** Дружелюбнее и короче, но подходит не всем; менять потом дорого — придётся переписывать весь интерфейс.

### 7.6. Статус вещи «Списано» (мелкое, вместе с картой экранов)

PRD §7.3 даёт примеры статусов, включая «списано». Для интерфейса — «Выбыло» — без бухгалтерского оттенка; альтернативы: «Списано» (как в PRD) или «Не используется». Остальные статусы называем: «Используется», «Хранится», «Требует ремонта», «Передано», «Продано».

## 8. Как менять словарь

- Новая сущность: строка в §2 появляется в том же PR, где сущность впервые показывается пользователю.
- Смена термина из §2 — решение Игоря. Формулировки сообщений — обычное ревью; GLM делает вторичную проверку на «не похоже на 1С» (MVP_PLAN §2).
- Самопроверка перед PR: нет слов из §4; у каждой сущности одно слово из §2; ошибки — по схеме «что случилось + что сделать».
- Документ держим короче 300 строк: новые примеры живут в задачах и PR, а не здесь.
