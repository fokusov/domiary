# ADR-006 — Формат исходников и работа с метаданными

**Status:** Proposed
**Date:** 2026-10-02
**Decider:** Igor Fokusov

## Context

- Конфигурация разрабатывается в 1С:Предприятии 8.5.1. Игорь выгрузил её из Конфигуратора в `src/` в иерархическом формате XML версии 2.21.
- Метаданные создаёт AI-агент (Claude). Основной инструмент агента — unica. unica пока поддерживает формат выгрузки только до 2.20 (8.3.27) и отказывается менять `src/`.
- Spike T-001 показал рабочий обходной путь: unica генерирует XML 2.20 в отдельном каталоге, Конфигуратор 8.5 в пакетном режиме загружает его во временную базу, проверяет и выгружает обратно в формате 2.21.
- Сборку APK и рабочую базу `base/` ведёт Игорь.

## Decision

### Формат и структура

1. **Исходники — XML-выгрузка Конфигуратора 8.5 (иерархическая), каталог `src/`.** EDT не используется.
2. **Каноничный вид `src/` — тот, что выдаёт `/DumpConfigToFiles` платформы 8.5.** Файлы, сгенерированные другими инструментами, попадают в `src/` только после цикла «загрузка → проверка → выгрузка».
3. Структура репозитория:

| Каталог | Содержимое | В git |
|---|---|---|
| `src/` | конфигурация | да |
| `tests/` | тесты (по ADR-007) и `tests/fixtures/` | да |
| `tools/` | скрипты проверки и нормализации | да |
| `docs/`, `docs/adr/`, `docs/spike/` | документация | да |
| `tasks/` | локальные задачи команды | нет |
| `base/` | рабочая база Игоря | нет |
| `pub/` | публикация мобильного приложения | нет |
| `.build/` | временные базы, логи, генерация unica | нет |

### Цикл изменения метаданных (только Claude)

```text
1. unica: каркас и объекты в .build/gen/src (формат 2.20)
2. копия объектов в src/ + регистрация в ChildObjects src/Configuration.xml
3. правка известных несовместимостей (см. ниже)
4. tools/normalize-src.ps1: загрузка во временную базу .build/ib → выгрузка в формате 2.21 → src/
5. tools/check-config.ps1: /CheckModules и /CheckConfig для контекстов мобильного приложения
6. коммит, PR
```

Шаги 4 и 5 появляются вместе с задачей T-007. До этого Claude выполняет их вручную теми же командами.

### Известные несовместимости шаблонов unica с мобильным приложением

| Что | Правило |
|---|---|
| Режим блокировок объекта `Automatic` | у каждого объекта `DataLockControlMode = Managed` |
| Двойная регистрация формы после `form.compile` + `form.add` | в `ChildObjects` объекта один `<Form>` на форму |

Список пополняется по мере работы, дубль ведётся в `AGENTS.md`.

### Обмен с Игорем

- Агенты не трогают `base/`. Игорь загружает `src/` из `main` в свою базу сам.
- Для проверки ветки Claude может передать Игорю `.cf` из временной базы.
- Изменения, которые Игорь сделал в Конфигураторе (например, настройки мобильного приложения), он выгружает в `src/` и коммитит отдельным PR. Агенты не правят эти настройки в XML вручную без его просьбы.

## Alternatives

**EDT.** Удобнее для командной разработки, но для мобильной платформы 8.5 поддержка не проверена, unica работает с форматом Конфигуратора, а Игорь собирает приложение из Конфигуратора. Отклонено.

**Ручная правка XML 2.21 без unica.** Нет генераторов и валидаторов для 8.5, высокий риск сломать выгрузку. Отклонено.

**Ждать поддержку 8.5 в unica.** Блокирует работу на неопределённый срок. Когда поддержка появится, шаги 1–3 упростятся, а шаги 4–5 останутся как проверка.

## Consequences

- Любое изменение метаданных проходит через временную базу: +1–2 минуты на цикл.
- Diff в PR показывает каноничную выгрузку 8.5, его можно ревьюить построчно.
- Параллельно метаданные меняет только один агент (AGENTS.md, правило 1), иначе конфликты в `Configuration.xml`.
- Проверка зависит от установленной платформы 8.5 на машине: в облачном CI её пока нет.
