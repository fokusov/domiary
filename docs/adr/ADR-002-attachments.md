# ADR-002 — Хранение вложений (фото и файлов)

**Status:** Proposed
**Date:** 2026-10-02
**Decider:** Igor Fokusov

## Context

- PRD требует фото вещей и документы: инструкции, чеки, гарантии, полисы (PRD §7, §17).
- ARCHITECTURE §12 оставила выбор: двоичные данные в базе, файлы в файловой системе приложения или гибрид.
- Приоритеты v1: надёжные резервная копия и восстановление важнее оптимизации под большие архивы (ARCHITECTURE §12).
- Spike T-001: фото с камеры и из галереи сохраняется в `ХранилищеЗначения` и читается обратно на эмуляторе без проблем. Отдельной работы с файловой системой spike не требовал.
- Ожидаемый объём: сотни вложений на дом (ARCHITECTURE §29), фото 200–500 КБ после сжатия.

## Decision

1. **Двоичные данные хранятся в базе приложения.** Файловая система устройства для постоянного хранения не используется.
2. **Отдельный регистр сведений `ДанныеВложений`**: измерение `Вложение` (→ `Вложения`), ресурс `Данные` (ХранилищеЗначения). В справочнике `Вложения` остаются только метаданные файла: имя, тип, размер, связь с владельцем.
   Причина: справочник читается в списках и формах постоянно, а двоичные данные нужны только при открытии файла. Так форма вещи не тянет мегабайты.
3. **Фото сжимается при съёмке**: `СделатьФотоснимок` с качеством 70 % и ограничением разрешения около 1600 px по длинной стороне. Выбранные из галереи файлы сохраняются как есть.
4. **Ограничение размера одного файла — 20 МБ.** Больше — понятное сообщение пользователю (словарь, §5).
5. **Миниатюры в v1 не создаются.** Если списки с фото окажутся медленными на реальном телефоне, миниатюры добавляются отдельным реквизитом-хранилищем и миграцией.
6. Все операции с вложениями — через общий модуль `Вложения`: `Добавить`, `Данные`, `Удалить`. Формы не пишут в регистр напрямую.

## Alternatives

**Файлы в каталоге приложения, путь в базе.** Меньше размер базы, но резервная копия должна собирать файлы отдельно, а при переустановке или очистке данных возможна рассинхронизация. Отклонено для v1.

**Двоичные данные реквизитом справочника `Вложения`.** Проще, но каждое чтение объекта тянет файл. Отклонено.

## Consequences

- Резервная копия содержит всё в одном месте (ADR-004).
- Размер базы растёт вместе с фото: при 500 фото по 300 КБ — около 150 МБ. Это приемлемо для телефона и проверяется замером в Фазе 1.
- `docs/METADATA.md`: реквизит `Вложения.Данные` заменяется регистром `ДанныеВложений`.
