# ADR-003 — Хроника (общая история событий)

**Status:** Proposed
**Date:** 2026-10-02
**Decider:** Igor Fokusov

## Context

PRD §19 требует общую историю событий с фильтрами по объекту, типу события и периоду. История вещи (PRD §7.4) — та же хроника с отбором по вещи.

ARCHITECTURE §13 выбрал направление: нормализованный регистр, который заполняют сервисы приложения (вариант B). Это решение нужно подтвердить и уточнить до модели метаданных.

## Decision

1. **Регистр сведений `Хроника`**, независимый, непериодический.
   - Измерение: `Идентификатор` (УникальныйИдентификатор).
   - Реквизиты: `Дата` (индекс), `ТипСобытия` (перечисление `ТипыСобытийХроники`, индекс), `Объект` (составная ссылка, индекс), `ОбъектНедвижимости` (индекс, для отбора по дому), `Источник` (составная ссылка на документ или справочник-источник, индекс), `Заголовок`, `Описание`, `Сумма`, `Валюта`.
2. **Хроника — производные данные.** Источник истины — документы, справочники и регистры предметных модулей. Хроника только отображает.
3. **Пишет в хронику только общий модуль `Хроника`**, в той же транзакции, что и запись источника:
   - `ДобавитьЗапись(...)` — новое событие;
   - `ОбновитьПоИсточнику(Источник)` — источник исправлен;
   - `УдалитьПоИсточнику(Источник)` — источник удалён.
   Формы и модули объектов в регистр напрямую не пишут.
4. **Хронику можно перестроить**: `Хроника.Перестроить()` удаляет все записи и заново создаёт их из источников. Вызывается после restore и после миграций, которые меняют источники (ARCHITECTURE §17, §18). Каждый предметный модуль отдаёт свои события через функцию `СобытияДляХроники()`.
5. **Типы событий v1**: покупка, перемещение, изменение статуса вещи, обслуживание, выполнение задачи, показания счётчика, оплата обязательства, пополнение накопления, операция по долгу, добавление документа.

## Alternatives

**Сборка истории запросом на лету (вариант A).** Нет дублирования, но запрос объединяет 8–10 таблиц, его трудно фильтровать и пагинировать на телефоне. Отклонено.

**Хроника как источник истины.** Проще писать, но история расходится с документами при исправлениях. Отклонено.

## Consequences

- Экран «История» и история вещи — один простой запрос к одному регистру с индексами.
- Каждый новый предметный модуль обязан реализовать `СобытияДляХроники()` и вызывать `Хроника` при записи.
- Нужен интеграционный тест: «перестроить хронику → результат совпадает с накопленной».
