# Spike T-001: Hello Domiary

**Статус:** проверено в тонком клиенте и на эмуляторе Android — все проверки пройдены (Игорь, 2026-10-02); реальный телефон — в процессе
**Ветка:** `spike/T-001-hello-domiary`
**Платформа:** 1С:Предприятие 8.5.1.1529, мобильная платформа 8.5

Цель: проверить возможности мобильной платформы, от которых зависят ADR-002 (вложения), ADR-004 (backup), ADR-005 (уведомления) и процесс работы с метаданными.

## Результаты, полученные без устройства

### 1. Процесс работы с метаданными (проверка 8)

Вопрос: можно ли создавать метаданные инструментами unica, которые поддерживают только формат выгрузки 2.20 (8.3.27)?

Ответ: **да, через промежуточную временную базу.**

1. unica генерирует объекты в отдельном каталоге в формате 2.20 (`.build/gen`, каркас `unica.cf.init`).
2. Объекты копируются в копию `src` и регистрируются в `Configuration.xml`.
3. Конфигуратор 8.5 в пакетном режиме загружает конфигурацию во временную файловую базу `.build/ib`: `/LoadConfigFromFiles` + `/UpdateDBCfg`. XML формата 2.20 загружается без ошибок.
4. Проверки `/CheckModules` и `/CheckConfig` для контекстов мобильного приложения.
5. `/DumpConfigToFiles` выгружает конфигурацию обратно в формате 2.21. Эта выгрузка и попадает в `src`.

Diff `src/Configuration.xml` после такого цикла содержит только новые строки в `ChildObjects`. Настройки мобильного приложения, которые задал Игорь, не меняются.

Рабочая база Игоря `base/` в этом процессе не участвует.

### 2. Найденные ловушки

| Что | Последствие | Как избежать |
|---|---|---|
| Шаблоны unica создают справочники и константы с `DataLockControlMode = Automatic` | `/CheckConfig` для мобильного приложения: «Мобильное приложение поддерживает только управляемый режим блокировок» | после генерации ставить `Managed` у каждого объекта |
| `ТекущаяУниверсальнаяДата()` недоступна на мобильном клиенте | ошибка компиляции модуля формы в контексте «Мобильное приложение-клиент» | на клиенте `УниверсальноеВремя(ТекущаяДата())` или получать дату с сервера |
| `unica.form.compile` + `unica.form.add` регистрируют форму в объекте дважды | дубликат `<Form>` в `ChildObjects` | после генерации формы проверять `ChildObjects` |
| `unica.form.add` отказывается работать, если `Form.xml` уже есть | — | сначала `form.add`, потом `form.compile` |
| `СредстваМультимедиа.СделатьФотоснимок` синхронный | `/CheckConfig -CheckUseModality` его **не** отмечает | проверить на устройстве, что вызов работает при `ModalityUseMode = DontUse` |

Эти правила нужно перенести в `AGENTS.md` и в задачу T-007 (скрипт проверки).

### 3. Проверки конфигурации

- `/CheckModules -ThinClient -Server -MobileAppClient -MobileAppServer -MobileClient`: синтаксических ошибок нет.
- `/CheckConfig` с теми же контекстами плюс `-IncorrectReferences -HandlersExistence -EmptyHandlers -ExtendedModulesCheck -CheckUseModality`: ошибок нет.

## Выводы

Игорь прошёл проверки в тонком клиенте и на эмуляторе Android: все работают. Подробные замеры (миллисекунды, размеры) в этот раз не записывались; таблица выше остаётся чек-листом для реального телефона.

Что это значит для решений:

1. **Метаданные (проверка 8).** Цикл через временную базу работает → ADR-006 принят, скрипты в `tools/`.
2. **Фото, галерея, сканирование (1a, 1b, 7).** Синхронный `СделатьФотоснимок` работает при отключённых модальных вызовах. Фото помещается в `ХранилищеЗначения` справочника → основа для ADR-002.
3. **Уведомления (2a–2c).** `ДоставляемыеУведомления.ДобавитьЛокальноеУведомление` работает → основа для ADR-005. Поведение после перезагрузки перепроверить на реальном телефоне.
4. **Файлы (3a, 3b, 4).** Выгрузка через «Поделиться» и сохранение файла работают без разрешения AllFilesAccess; чтение выбранного файла работает → основа для ADR-004 и решения по разрешениям (T-003).
5. **Обновление поверх (6).** Данные сохраняются при установке новой версии → механизм миграций (`Миграции`, T-013) опирается на это.

Spike-код остаётся в ветке `spike/T-001-hello-domiary` и в `main` не попадает.
