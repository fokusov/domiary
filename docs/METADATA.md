# Domiary — модель метаданных v1

**Статус:** утверждено Игорем 2026-10-02 (решения §9 — по рекомендациям)
**Основа:** ARCHITECTURE §4–§10, §13; ADR-001 (имена), ADR-003 (хроника), ADR-008 (задачи, повторяемость, гарантия); UX_MAP; GLOSSARY.

Список объектов конфигурации v1, их реквизиты и связи. Имена — по ADR-001. Синоним каждого объекта — термин из словаря (`docs/GLOSSARY.md`), он и виден пользователю.

Обозначения типов: `Строка(N)`, `Число(N,M)` (неотрицательное, если не сказано иное), `Дата`, `ДатаВремя`, `Булево`, `→ Объект` — ссылка, `Хранилище` — ХранилищеЗначения.

Общие правила для всех объектов (ADR-006):

- `DataLockControlMode = Managed`;
- справочники без кода (`CodeLength = 0`), наименование — `Строка(150)`;
- у справочников с флагом `Архив` удаление заменено архивированием: история сохраняется (ARCHITECTURE §2.6).

## 3. Документы

Все документы проводятся в обычном режиме (не оперативно), нумерация не показывается пользователю. Каждый документ при записи вызывает `Хроника` (ADR-003).

| Документ | Реквизиты шапки | Движения |
|---|---|---|
| `ПокупкаВещи` | Вещь, Сумма, Валюта, Продавец, Заметка | кэш полей покупки в `Вещи`; `Хроника` |
| `ПеремещениеВещи` | Вещь, ИзОбъекта, ИзМеста, ВОбъект, ВМесто, Заметка | `МестонахождениеВещей`; кэш в `Вещи`; `Хроника` |
| `ВыполнениеОбслуживания` | Вещь, Правило → `ПравилаОбслуживания`, ВидРаботы Строка(150), Стоимость, Валюта, Исполнитель Строка(150), Заметка | `ГрафикОбслуживания`; `Хроника` |
| `ПоказанияСчетчика` | Счетчик, Заметка; табличная часть `Значения`: НомерТарифа Число(1,0), Значение Число(15,3), Расход Число(15,3) | `Хроника` |
| `ОплатаОбязательства` | Обязательство, Период Дата (месяц срока), Сумма, Валюта, Счет → `Счета`, Заметка | `Хроника` |
| `ПополнениеНакопления` | Цель → `ЦелиНакоплений`, Сумма, Валюта, Счет → `Счета`, Заметка | `Накопления`; `Хроника` |
| `ОперацияПоДолгу` | Долг, ВидОперации → `ВидыОперацийПоДолгу`, Сумма, Заметка | `ОстаткиДолгов`; `Хроника` |

`Расход` в `ПоказанияСчетчика` вычисляет `СчетчикиКлиентСервер` по предыдущим показаниям при записи и хранится, чтобы история не пересчитывалась задним числом.

`ОплатаОбязательства.Счет` и `ПополнениеНакопления.Счет` — только для информации, остаток счёта не меняют (ARCHITECTURE §6.6).

## 4. Регистры сведений

| Регистр | Периодичность / режим | Измерения | Ресурсы и реквизиты |
|---|---|---|---|
| `МестонахождениеВещей` | по позиции регистратора, подчинён `ПеремещениеВещи` | Вещь | ОбъектНедвижимости, Место |
| `СтатусыВещейИстория` | секунда, независимый | Вещь | Статус; реквизит Заметка |
| `ГрафикОбслуживания` | непериодический, независимый* | Правило | ПоследнееВыполнение, СледующийСрок |
| `ВыполненияЗадач` | непериодический, независимый | Задача, Идентификатор | Дата, Заметка |
| `Хроника` | непериодический, независимый | Идентификатор | Дата, ТипСобытия, Объект, ОбъектНедвижимости, Источник, Заголовок, Описание, Сумма, Валюта (ADR-003). Ссылочные поля `Объект`, `ОбъектНедвижимости`, `Источник` добавляются в Фазе 1, когда появятся справочники и документы |
| `СостояниеПриложения` | непериодический, независимый | Ключ Строка(50) | Значение Строка(0) |

\* В ARCHITECTURE §8.4 регистр подчинён документу. Но первая запись графика нужна сразу при создании правила, до первого выполнения, поэтому `ГрафикОбслуживания` — независимый регистр, который пишет сервис `Обслуживание`; документ `ВыполнениеОбслуживания` вызывает сервис при проведении. Измерение `Вещь` из ARCHITECTURE §8.4 не нужно: правило уже принадлежит вещи.

`СостояниеПриложения` хранит: версию данных, идентификатор установки, дату последней резервной копии, признаки миграций (ARCHITECTURE §8.8).

Индексы: `Хроника.Дата`, `Хроника.Объект`, `Хроника.ОбъектНедвижимости`, `Хроника.Источник`, `ГрафикОбслуживания.СледующийСрок`.

## 5. Регистры накопления

| Регистр | Вид | Измерения | Ресурс | Регистратор |
|---|---|---|---|---|
| `Накопления` | остатки | Цель | Сумма | `ПополнениеНакопления` |
| `ОстаткиДолгов` | остатки | Долг | Сумма | `ОперацияПоДолгу` |

Начальная сумма долга — первая операция `ОперацияПоДолгу` с видом «Возникновение», её создаёт сервис `Финансы` при записи нового долга. Так остаток всегда считается только из документов.

`AccountBalances` (ARCHITECTURE §8.5) в v1 не создаётся.

## 8. Подсистемы (разделы интерфейса)

По карте экранов: `Главная`, `Вещи`, `Задачи`, `Финансы`, `Ещё`. Состав каждой подсистемы задаётся при реализации срезов. Служебные объекты (регистры, `СостояниеПриложения`) в интерфейс не включаются.

Роли в v1 не нужны: в мобильном приложении нет пользователей. Если они понадобятся для проверки в тонком клиенте, достаточно одной роли `ПолныеПрава`.

## 9. Решения (утверждены 2026-10-02)

1. **Валюта.** Одна валюта в интерфейсе v1 (константа `ОсновнаяВалюта`); поле `Валюта` в денежных объектах хранится с первого дня, чтобы мультивалютность не потребовала миграции.
2. **`ПокупкаВещи` — отдельный документ**, как в ARCHITECTURE §6.4. При быстром добавлении вещи с ценой сервис создаёт его сам.
3. **`ГрафикОбслуживания` — независимый регистр** (сноска §4); ARCHITECTURE §8.4 обновлена.
