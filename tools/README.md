# Проверка исходников 1С

Требуются Windows, PowerShell 7 и установленная платформа 1С 8.5.
Для нормализации также нужны Git и штатный Windows `robocopy`.
Мобильный сборщик не запускается; `base/` и `pub/` не используются.

```powershell
pwsh -File tools/check-config.ps1
pwsh -File tools/check-config.ps1 -Clean
pwsh -File tools/check-config.ps1 -Source 'C:\Temp\test src' -V8Path 'C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe'
pwsh -File tools/normalize-src.ps1
```

Относительный `-Source` считается от корня проекта, а не текущего каталога.
Платформа выбирается в порядке: `-V8Path`, `V8_PATH`, самая новая версия
`C:\Program Files\1cv8\8.5.*\bin\1cv8.exe` (сравнение числовых версий).

## check-config.ps1

Создаёт или переиспользует `.build/ib`, загружает исходники с обновлением БД,
последовательно проверяет модули и конфигурацию в пяти контекстах: тонкий
клиент, сервер, мобильное приложение (клиент и сервер), мобильный клиент.
Проверка конфигурации включает ссылки, обработчики, расширенную проверку
модулей и использование модальности. `-Clean` удаляет только временную базу.
Выводит код каждого шага и полный лог, включая строки ошибок и фрагменты BSL.

| Код | Значение |
|---|---|
| 0 | Обе проверки завершились без ошибок |
| 1 | Проверка модулей или конфигурации вернула 101 (ошибки проверки) |
| 2 | Не найдены исходники/платформа, база занята, ошибка создания/загрузки/запуска или неожиданный код платформы |

## normalize-src.ps1

Пересоздаёт `.build/ib`, загружает `-Source` с обновлением БД и выгружает
иерархические исходники в свежий `.build/dump`. Только после успешных загрузки
и выгрузки зеркалит результат **в указанный `-Source`** (по умолчанию `src`).
Это канонизирует XML средствами установленной платформы 8.5, в том числе
после генераторов формата 2.20. `ConfigDumpInfo.xml` и `DumpFilesIndex.txt`
исключены из копирования и удаления; существующие файлы остаются неизменными.
В конце выводит `git status --short src`; для другого Source внутри проекта
дополнительно показывает его статус. Внешний каталог не обязан быть Git-репозиторием.

**Зеркалирование удаляет лишние файлы в Source.** Перед запуском сохрани
свои изменения в Git. Зеркалирование не является атомарным: при ошибке диска
возможен частично обновлённый каталог; полная выгрузка остаётся в `.build/dump`.
Код 0 означает успех, 2 — ошибку, включая ошибку копирования или Git.

## Временные файлы и ограничения

Логи UTF-8 читаются через `Get-Content -Encoding utf8` и лежат в
`.build/logs/{create,load,modules,config,dump}.log`; лог каждого выполненного
шага перезаписывается, остальные могут относиться к предыдущему запуску.
Вся `.build/` исключена из Git.

Оба скрипта удерживают эксклюзивный `.build/config.lock` на весь запуск:
параллельный запуск завершается с кодом 2. Не открывай `.build/ib` вручную
во время выполнения. Оставшийся файл lock сам по себе не блокирует запуск.
Ссылки/junction в используемых каталогах запрещены; Source не может
пересекаться с `base/`, `pub/` и рабочими каталогами скриптов.

## Проверки при разработке (8.5.1.1529)

Исходный HEAD совпадал с `main`. Отрицательные сценарии выполнялись только
на копиях в `.build/`, в том числе с пробелами в пути.

| Сценарий | Результат |
|---|---|
| `check-config.ps1 -Clean` на исходниках main | 0; обе проверки платформы: 0 |
| В копии добавлен `Ext/ManagedApplicationModule.bsl` с `Процедура Сломано(` | 1; обе проверки: 101, выведено местоположение ошибки `(2,1)` |
| Повторная проверка main без `-Clean` после сломанной копии | 0; старый модуль не остался в базе |
| `normalize-src.ps1` на main | 0; `git status --short src` пуст |
| Нормализация копии с двумя исключёнными служебными файлами | 0; SHA-256 всех файлов до/после совпали |
| Незакрытый XML-тег в `Configuration.xml` копии | Оба скрипта: 2; нормализация сохранила SHA-256 исходников |
| Второй запуск при удерживаемом lock / отсутствующий `-V8Path` | 2 / 2 |

Реальный лог проверки начинается с BOM `EF BB BF`; русский текст корректно
читается как UTF-8. Проверки платформы не заменяют приёмку на устройстве.
